Usage:
  newserv [ACTION] [OPTIONS...]

If ACTION is not specified, newserv runs in server mode. PSO clients can
connect normally, join lobbies, play games, and use the proxy server. See
README.md and system/config.json for more information.

When ACTION is given, newserv will do things other than running the server.

Some actions accept input and/or output filenames; see the descriptions below
for details. If INPUT-FILENAME is missing or is '-', newserv reads from stdin.
If OUTPUT-FILENAME is missing and the input is not from stdin, newserv writes
the output to INPUT-FILENAME.dec or a similarly-named file; if OUTPUT-FILENAME
is '-', newserv writes the output to stdout. If stdout is a terminal and the
output is not text or JSON, the data written to stdout is formatted in a
hex/ASCII view; in any other case, the raw output is written to stdout, which
(for most actions) may include arbitrary binary data.

The actions are:
  help
    You're reading it now.
  version
    Show newserv's revision and build date.
  compress-prs [INPUT-FILENAME [OUTPUT-FILENAME]]
  compress-pr2 [INPUT-FILENAME [OUTPUT-FILENAME]]
  compress-prc [INPUT-FILENAME [OUTPUT-FILENAME]]
  compress-bc0 [INPUT-FILENAME [OUTPUT-FILENAME]]
    Compress data using the PRS, PR2, PRC, or BC0 algorithms. By default, the
    heuristic-based compressor is used, which gives a good balance between
    memory usage, CPU usage, and output size. For PRS and PR2, this compressor
    can be tuned with the --compression-level=N option, which specifies how
    aggressive the compressor should be in searching for literal sequences. The
    default level is 0; a higher value generally means slower compression and a
    smaller output size. If the compression level is -1, the input data is
    encoded in a PRS-compatible format but not actually compressed, resulting
    in valid PRS data which is about 9/8 the size of the input.
    There is also a compressor which produces the absolute smallest output
    size, but uses much more memory and CPU time. To use this compressor, use
    the --optimal option.

  decompress-bc0 [INPUT-FILENAME [OUTPUT-FILENAME]]

  prs-size [INPUT-FILENAME]

  disassemble-bc0 [INPUT-FILENAME]

    debugging the compressors and decompressors themselves.
  encrypt-data [INPUT-FILENAME [OUTPUT-FILENAME] [OPTIONS...]]
  decrypt-data [INPUT-FILENAME [OUTPUT-FILENAME] [OPTIONS...]]
    Encrypt or decrypt data using PSO's standard network protocol encryption.
    By default, PSO V3 (GameCube/XBOX) encryption is used, but this can be
    overridden with the --pc or --bb options. The --seed=SEED option specifies
    the encryption seed (4 hex bytes for PC or GC, or 48 hex bytes for BB). For
    BB, the --key=KEY-NAME option is required as well, and refers to a .nsk
    file in system/blueburst/keys (without the directory or .nsk extension).
    For non-BB ciphers, the --big-endian option applies the cipher masks as
    big-endian instead of little-endian, which is necessary for some GameCube
    file formats.
  encrypt-trivial-data --seed=BASIS [INPUT-FILENAME [OUTPUT-FILENAME]]
  decrypt-trivial-data [--seed=BASIS] [INPUT-FILENAME [OUTPUT-FILENAME]]
    Encrypt or decrypt data using the Episode 3 trivial algorithm. When
    encrypting, --seed=BASIS is required; BASIS should be a single byte
    specified in hexadecimal. When decrypting, BASIS should be specified the
    same way, but if it is not given, newserv will try all possible basis
    values and return the one that results in the greatest number of zero bytes
    in the output.

  decrypt-dcv2-executable --executable=EXEC --indexes=INDEXES --values=VALUES
  decrypt-dcv2-executable --executable=EXEC --simple [--seed=SEED]
    Decrypt a PSO DC v2 executable file. EXEC should be the path to the
    executable (DP_ADDRESS.JPN), INDEXES should be the path to the index fixup
    table (KATSUO.SEA), and VALUES should be the path to the value fixup table

  encrypt-dcv2-executable --executable=EXEC --indexes=INDEXES
  encrypt-dcv2-executable --executable=EXEC --simple --seed=SEED
    Encrypt a PSO DC v2 executable file. EXEC should be the path to the
    executable (DP_ADDRESS.JPN) and INDEXES should be the path to the index
    fixup table (KATSUO.SEA). The output is written to EXEC.enc and
    INDEXES.enc.
    If --simple is given, uses the simpler encryption method used in Ives'
    Enhancement Pack. In this case, --seed is required.

  find-decryption-seed OPTIONS...
    Perform a brute-force search for a decryption seed of the given data. The
    ciphertext is specified with the --encrypted=DATA option and the expected
    plaintext is specified with the --decrypted=DATA option. The plaintext may
    include unmatched bytes (specified with the Phosg parse_data_string ?
    operator), but overall it must be the same length as the ciphertext. By
    default, this option uses PSO V3 encryption, but this can be overridden
    with --pc. (BB encryption seeds are too long to be searched for with this
    function.) By default, the number of worker threads is equal to the number
    of CPU cores in the system, but this can be overridden with the
    --threads=NUM-THREADS option.

  decode-qst INPUT-FILENAME [OPTIONS...]
    Decode the input quest file into a compressed, unencrypted .bin or .dat
    file (or in the case of decode-qst, both a .bin and a .dat file).
    INPUT-FILENAME must be specified, but there is no OUTPUT-FILENAME; the
    output is written to INPUT-FILENAME.dec (or .bin, or .dat). If the output
    is a .dec file, you can rename it to .bin or .dat manually. DLQ and QST
    decoding are relatively simple operations, but GCI and VMS decoding can be
    computationally expensive if the file is encrypted and doesn't contain an
    embedded seed. If you know the player's serial number who generated the
    GCI or VMS file, use the --seed=SEED option and give the serial number (as
    a hex-encoded 32-bit integer). If you don't know the serial number,
    newserv will find it via a brute-force search, which will take a long time.

Most options that take data as input also accept the following option:
  --parse-data
      For modes that take input (from a file or from stdin), parse the input as
      a hex string before encrypting/decoding/etc.

Many versions also accept or require a version option. The version options are:
  --pc-patch: PC patch server
  --bb-patch: BB patch server
  --dc-nte: DC Network Trial Edition
  --dc-proto or --dc-11-2000: DC 11/2000 prototype
  --dc-v1: DC v1
  --dc-v2 or --dc: DC v2
  --pc-nte: PC Network Trial Edition
  --pc: PC v2
  --gc-nte: GC Episodes 1&2 Trial Edition
  --gc: GC Episodes 1&2
  --xb: Xbox Episodes 1&2
  --ep3-nte: GC Episode 3 Trial Edition
  --ep3: GC Episode 3
  --bb: Blue Burst
